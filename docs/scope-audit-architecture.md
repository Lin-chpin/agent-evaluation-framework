# AI 代码变更范围辅助审计：当前架构

`audit-scope` 根据需求、验收标准和两个 commit 之间的 Git Diff，使用确定性规则与可选语义辅助整理审计发现，并运行 Diff 选择出的可用测试。它帮助审阅者更快找到值得检查的改动，不自动批准、合并或发布代码。

## 正式判断链路

```text
需求 / 验收标准 / 可选路径约束 + base、target commit
                         ↓
                      Git Diff
                         ↓
                  确定性范围检查
                         ↓
                  可选本地 JSON Judge
                         ↓
       模型发现的文件、侧别与变更行证据校验
                         ↓
       Diff 驱动测试选择与可用用例执行
                         ↓
 scope_audit.json + report.md + diff.patch + 测试报告
                         ↓
                    Human Review
```

## 职责

- **程序负责确定性事实。** `forbidden_paths` 命中会标为明确越界；超出声明允许路径、未要求的公开声明等会形成疑似发现。缺少需求或验收标准、路径范围不足时保留证据不足。
- **LLM 负责语义辅助。** 可选本地 JSON Judge 根据需求、验收标准和 Diff 补充语义发现。它不能撤销确定性明确越界或疑似越界规则；出现冲突时保留各自发现并提示人工复核。
- **程序校验模型 evidence。** 每条模型发现必须指向 Diff 中实际改变的文件、正确的 `base` 或 `target` 侧及变更行。无法通过校验的发现会被拒绝并记录原因。一个文件可保留多条独立发现；完全重复的模型发现会合并。坐标有效只证明所引位置发生了变化，不证明语义判断正确。
- **测试验证选中的行为。** Diff 选择 `smoke`、`regression` 或 `full` 套件，评测引擎运行所提供且可用的 case。测试仅证明这些 case 的实际结果，不能证明没有越界修改。只有目标仓库检出目标 commit 且工作区干净时才执行测试；未执行和未覆盖的情况会进入报告。
- **报告保留处理轨迹。** `scope_audit.json` 保存状态、证据、测试选择、运行情况、警告和模型发现的校验/保留/拒绝记录；`report.md` 面向审阅者呈现结论和待处理项；`diff.patch` 保存被审计的完整 Diff。

## Human-in-the-loop

自动发现用于缩小人工 Review 范围。普通疑似发现、规则与语义冲突、证据不足、测试失败或覆盖缺口交由人工检查需求、Diff、证据与实际测试结果。人工决定修改是否在 Scope 内，并将 Scope 与 Risk 分开判断。需求没有定义的行为契约不能由系统自行补全，应先由需求或接口负责人澄清。

明确禁止路径由任务给定的规格确定；如果禁止范围本身有误，需要先修订规格再审计。退出码 `0` 表示本次未发现明显问题，`1` 表示命中明确禁止路径，`2` 表示需要复核或证据不足。退出码不是人工批准。框架保存自动报告和处理轨迹，但不代替人工签署或持久化最终业务裁决。

## 真实能力边界

- 审计结果依赖需求、验收标准和路径约束是否完整、明确。
- 语义判断可能不确定；Diff 行证据只能证明代码位置确有变化，不能单独证明该变化违反需求。
- 测试通过只说明所运行用例通过，不代表所有影响都已覆盖，也不证明变更范围合规。
- 该流程用于辅助人工 Code Review，不是自动 Scope 判决、发布门禁或生产准确率保证。
