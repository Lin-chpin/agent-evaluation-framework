# Scope Audit 架构与人工交接

`audit-scope` 是代码变更范围审计的辅助决策流程，不是自动批准或发布门禁。输入是需求、验收标准、路径约束和两个 commit；输出是可追溯的自动发现、测试执行情况与待人工确认的问题。

## 当前判断链路

```text
需求与验收标准 + 两个 commit
        ↓
DiffSnapshot → 确定性范围规则 → 可选本地 JSON Judge
        │                         ↓
        │               校验文件、base/target 侧、真实变更行
        │                         ↓
        │               保留 / 拒绝 / 精确重复合并及原因
        └→ 既有测试选择 → 可用 case 执行
                                  ↓
          scope_audit.json + report.md + diff.patch + 套件报告
                                  ↓
                             人工确认范围结论
```

- `scope_audit.py` 对显式禁止路径给出确定性明确越界；普通允许路径外修改、未要求的公开声明等是疑似告警。当前疑似路径规则进入最终发现，模型的“合理关联”结论不会自动撤销它。
- 可选 Judge 的每条发现必须落在本次 Diff 对应文件和 `base`/`target` 侧的真实变更行。`model_finding_trace` 记录原始发现、校验与保留/拒绝/去重结果。**坐标合法不保证理由正确或修改越界。**
- `test_selection.py` 复用同一 Diff 选择套件；既有评测引擎执行可用 case。`reporting.py` 保存实际执行、未执行与未覆盖风险。测试通过只覆盖所运行的 case，不能清除范围告警。
- CLI 仅在规则命中明确禁止路径时返回明确越界（退出码 `1`）；其他告警或测试失败返回需复核（`2`），证据不足也返回 `2`。`0` 只表示本次未发现明显问题。

## Human-in-the-loop 决策

审阅者以自动报告为输入，核对需求和验收标准、跨文件修改的技术必要性、原始 Diff、每条发现的代码与语义依据，以及测试通过、失败、未执行和未覆盖情况。**Scope** 问修改是否获需求授权或为完成需求所必需；**Risk** 问即使修改合理是否可能造成回归。风险提示不能单独升级为越界结论。

对普通路径疑似、规则与模型冲突、证据不足、模型发现被拒绝或测试覆盖缺口，保留人工待审状态。若需求没有定义某项可观察行为的契约，例如 getter 返回的 `List` 对象 identity，应请需求或接口负责人裁定，不能依据潜在风险强判合理或越界。显式禁止路径不会被模型自行推翻；若路径约束本身有误，先由任务负责人修订规格并重新审计。

当前 `audit-scope` 保存自动报告和模型发现轨迹，**没有内建人工裁决的持久化或自动覆盖机制**。人工最终结论及其依据应由使用该报告的项目流程另行记录；不能把自动结论、退出码或测试通过当成人工签署。

## 已知能力边界

- 小规模外部改造样本表明，普通跨路径规则可能把技术上必要的关联修改报为疑似；当前正式实现仍保留这种告警供人工审阅。离线语义仲裁原型没有进入正式链路。
- 严格变更行校验能拒绝无效行号，却不能证明模型理由与代码对应。隔离 Evidence Grounding 对抗实验曾把**只描述旧侧代码**的发现映射到真实新增行，构成错误语义 evidence；因此自动定位原型也未进入正式链路。唯一词法候选仍需验证所引片段与 old/new 侧及具体替换关系。
- 对象 identity 争议样本的节点身份要求与返回列表身份不同。现有需求、测试和调用上下文没有足够依据裁定列表身份是否属于 Scope 契约，应作为规格待裁问题，不能用它证明模型正确或错误。
- 当前实验使用少量真实变更提取与改造样本及封存模型响应，只支持定位这些失败模式，不代表生产环境准确率；正式审计仍依赖完整业务规格、可用回归 case 和人工判断。
