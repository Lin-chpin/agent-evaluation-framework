## 可运行验证

在项目根目录，使用 Python 3.11 或以上版本：

```powershell
python -m unittest discover -s tests -p test_scope_audit.py -v
python -m unittest discover -s tests -v
```

第一条会重建隔离仓库并验证正常修改、明确越界、隐式新增公开行为、合理跨模块关联、缺失需求、空 Diff、模型证据位置不合法、模型不确定、模型与规则冲突、删除行定位、适配器异常、脏工作区和回归失败。第二条确认原有功能仍通过；本次最终完整回归 68/68 通过，其中新增审计测试 8 项，失败 0 项，完整日志见 [unit-tests.txt](unit-tests.txt)。CLI 帮助入口（源码 PYTHONPATH）与 git diff --check 也通过。

## 效果与限制

- 正常和合理关联两个受控样例未观察到误报；明确禁止修改和未要求的公开函数扩展两个样例未观察到漏报。这不是代表性数据集的误报率或漏报率。
- 缺失验收信息、无法执行测试、空 Diff 和模型不确定会保留证据不足或需复核；测试失败会阻止输出“未发现明显问题”。
- 明确禁止路径可确定性判定。路径越出允许范围、公开声明、CLI、依赖和默认设置的词法特征只产生疑似越界。允许路径本身不证明其中的每段修改都合理。
- 函数内部的隐式行为变化、是否必要的重构和跨模块真实因果依赖需要语义复核与业务 case。词法规则会漏掉没有明显表面特征的变化，也可能把合理公开声明变化标为疑似。
- 当前每个文件保留一个主要发现；没有完整枚举同一文件的多项问题或证明完整回归覆盖。
- 未配置 AGENT_EVAL_MODEL，因此未调用真实模型。模型接口测试使用固定响应，只验证接入、证据校验、异常和冲突处理；概率性误报、漏报与重复稳定性尚未测量。
- 原有框架选择的是预先提供的 regression/smoke/full case 套件；任意项目的原生测试仍由 ProjectAdapter 接入。适配器必须实际执行目标版本，框架不能从任意适配器代码中证明这一点。

后续有价值的验证是冻结人工标注的真实需求与 Diff 样本，接入本地模型重复运行，分别统计四类结论、误报、漏报和稳定性；有多项问题被单文件汇总隐藏的实际样例后，再增加多个发现。
