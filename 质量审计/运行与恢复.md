# 运行与恢复审计

## 0.4.0 审计发现

2026-08-31 的框架审计复现了三个输入完整性问题。

- 空测试集返回 `passed`，结果数为 0。
- 同一运行中出现重复 `case_id` 时，SQLite 主键与 `INSERT OR REPLACE` 会让后写结果覆盖先写结果。
- `resume=True` 只按 `run_id + case_id` 跳过历史结果，没有确认当前 case 内容、适配器、suite、source 和执行配置仍与原运行一致。

这三项属于框架自身的正确性问题，与业务数据质量无关。

## 0.4.1 修复结果

以下验收项均已完成。

- 空测试集在创建运行前失败。
- 空 `case_id` 或重复 `case_id` 在启动并发任务前失败，不产生部分结果。
- 新运行保存全部 case 的规范化身份哈希。
- 恢复时已有 case 不得缺失或改变；允许在保持历史 case 不变时追加新 case。
- 恢复时适配器、suite、source 和稳定执行配置必须匹配。
- 旧数据库缺少 case 身份记录且已经保存结果时，拒绝不安全恢复。

恢复语义是追加式恢复，不是任意修改后的结果复用。历史 case 和运行身份保持不变时可以增加新 case；删除、改写或更换运行身份会在复用旧结果前失败。以上行为由 `tests/test_run_integrity.py` 的 5 项测试覆盖。
