# 评测 Skill 自进化

## 特殊之处

普通 Skill 的 badcase 是输出或行为不符合业务预期。评测 Skill 的 badcase 是它对某个 case 的判断与人工确认结果或 gold 不一致。两者共享“执行、Trace、发现问题、人工审核、候选修改、回归测试”的外层闭环，但数据谱系和评价口径必须独立。

## 独立测试集

- 人工确认正确的历史报告进入 regression。
- 人工确认错误或部分正确的报告连同 gold 修正进入 improvement。
- 另行冻结未向候选生成暴露的 holdout。
- 修改后同时回放历史错误、原本正确案例和 holdout。

每条样本至少保存原始 case、被测对象版本、评测 Skill 版本、原报告、人工结论、gold 修正、审核时间和来源。

## Gold 也可能有歧义

业务方并不总能一次给出确定事实或唯一 gold。REVIEW-007 与 REVIEW-008 首次都被审核为“正确”，复核后裁决为“部分正确”，二值门禁才确定为 `INCORRECT`。这个过程必须作为审核历史保存，不能把首次判断静默覆盖掉。

未裁决样本应标为 `UNRESOLVED`：只进入待审核区，不参与候选生成、回归门禁、holdout 或公开准确率分母。完成复核后才写入最终角色，同时保留首次判断、复核意见和裁决人/时间。

## 评价与不变量

- 统计人工一致率、误报率、漏报率、结构字段准确率和重复评分稳定性。
- 无法结构化的解释文本保留人工复核，不让另一个未校准 LLM 成为唯一真值。
- 候选不能修改人工审核结果、gold、数据集角色或确定性硬门禁。
- baseline 和 candidate 必须使用同一冻结样本；holdout 不向候选生成暴露。
- 评测 Skill 可以启用严格 holdout 门禁；任何人工确认的 holdout 错误都会阻止晋级，不能用总体改善抵消。
- 审计同时记录被测对象版本、评测 Skill 版本和数据集哈希。
- 候选通过后只进入待人工批准，不自动替换正在使用的评测 Skill。
