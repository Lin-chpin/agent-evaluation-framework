# 评测 Skill 自进化

## 评测 Skill 的专属能力

普通 Skill 的 badcase 是输出或行为不符合业务预期。评测 Skill 的 badcase 是它对某个 case 的判断与人工确认结果或 gold 不一致。两者共享执行、Trace、问题发现、人工审核、候选修改和回归测试流程，评测 Skill 额外保留独立的数据谱系和评价口径。

## 独立测试集

- 人工确认正确的历史报告进入 regression。
- 人工确认错误或部分正确的报告连同 gold 修正进入 improvement。
- 另行冻结未向候选生成暴露的 holdout。
- 修改后同时回放历史错误、原本正确案例和 holdout。

每条样本至少保存原始 case、被测对象版本、评测 Skill 版本、原报告、人工结论、gold 修正、审核时间和来源。

## Gold 审核与复核

业务方可以通过复核流程持续完善 Gold。REVIEW-007 与 REVIEW-008 首次被审核为“正确”，复核后裁决为“部分正确”，二值门禁随后确定为 `INCORRECT`。框架完整保存首次判断、复核意见和最终裁决，方便追踪评价口径的变化。

未裁决样本标为 `UNRESOLVED`，先进入待审核区。完成复核后再写入最终角色，并保留首次判断、复核意见和裁决人、时间等历史信息。

## 评价与不变量

- 统计人工一致率、误报率、漏报率、结构字段准确率和重复评分稳定性。
- 无法结构化的解释文本保留人工复核，Gold 由业务审核过程持续确认。
- 候选修改与人工审核结果、Gold、数据集角色和确定性硬门禁分开管理。
- baseline 和 candidate 必须使用同一冻结样本；holdout 不向候选生成暴露。
- 评测 Skill 可以启用严格 holdout 门禁，保护留出样本的质量要求。
- 审计同时记录被测对象版本、评测 Skill 版本和数据集哈希。
- 候选通过后进入人工批准流程，再决定是否替换正在使用的评测 Skill。
